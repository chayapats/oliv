# Personal finetune corpus

Builds the training set for finetuning the shipped STT model (`typhoon-whisper-turbo`)
onto one voice — yours. Not for distribution: overfitting to you is the goal, not a bug.

## Why this exists

The shipped pipeline recovers a mangled English term *after* the fact, with
`dictionary.py`, `phonetic.py` and the Gemma cleanup. That works when typhoon still
leaves a recognisable trace of the word. When it doesn't, nothing downstream can help —
and the cleanup will confidently rewrite the wreckage into something plausible and wrong:

```
said     ...แล้ว merge branch main ด้วยนะ
typhoon  ...แล้วเมิร์ชแบรนด์เมนด้วยนะ         ← "branch main" misheard
cleanup  ...แล้ว merge brand name ด้วยนะ      ← repaired into the wrong words
```

Only a finetune fixes that class of error. `build_terms.py` finds those terms from the
eval results rather than guessing at them.

## Pipeline

```
matching.py      the ONE term matcher + the ONE leak predicate
evalcorpus.py    the eval sentences; fails closed on missing OR empty manifests
build_terms.py   4 sources -> terms.jsonl + TERMS_REVIEW.md
   (workflow)    terms -> ~2,450 sentences         [Claude, style-anchored on your corpus]
build_script.py  raw sentences -> script.jsonl     [term fidelity, leak guard, dedup]
record.py        script.jsonl -> dataset/clips/    [hold-space recorder + QC]
verify.py        does this audio SAY this sentence?
export.py        takes -> dataset/train.jsonl,val.jsonl  [fails closed]
probe.py         the forgetting probe: eval clips with NO trained term
lora.py          LoRA for mlx-whisper (identity at init, merge-equivalent)
targets.py       token targets matching the decode path OLIV actually takes
train.py         MLX-native LoRA finetune, in place on the shipped weights
test_finetune.py 105 assertions; every one is a bug that was real
```

Corpus tooling and training run from `benchmark/.venv` — the leak guard needs a Thai tokeniser
and verification needs the model:

```sh
benchmark/.venv/bin/python benchmark/finetune/test_finetune.py
```

**Evaluation is the exception: it runs from `sidecar/.venv`.** The Gemma cleanup imports
`mlx_lm`, and `import mlx_lm` *raises* under `benchmark/.venv` (mlx_lm 0.31.3 calls
`AutoTokenizer.register()` with a string where transformers 5.13 demands a class). Anything that
touches the cleanup pipeline dies on import there.

**The invariants:** no label comes from the eval corpus (absolute). A label says what was
spoken into its audio (96.5% of skipped words caught, 100% of wrong-sentence reads). Audio
whose speech is not the label never ships — but *noisy* audio with a correct label is fine
and even useful, so nothing gates on room quality.

**Not guaranteed:** ~3.5% of skipped short words (`p99` leaves a one-character hole). See
`verify.py`, which says so in the code rather than in a changelog.

### 1. Terms

```sh
python3 benchmark/finetune/build_terms.py
```

| source | what it contributes |
|---|---|
| `terms_manual.txt` | terms you add by hand — authoritative |
| eval_results | terms the shipped pipeline **provably** loses. The highest-value source |
| `dictionary.py` | the TRANSLIT / CANONICAL_CASE map you already curated |
| git log + docs | nominations only; a term must look like a proper noun to survive |

Read `TERMS_REVIEW.md`, promote anything real out of the P2 nominations into
`terms_manual.txt`, re-run. Quota is a **coverage target** (how many times a term must
occur across the script), not a sentence count — one sentence carries ~3 terms.

### 2. Script

Generated by a Claude workflow, style-anchored on the 194 sentences you wrote in
`data/manifest_all.jsonl`. Then:

```sh
python3 benchmark/finetune/build_script.py _generated.json
```

which enforces, in order: **term fidelity** (present at a word boundary, spelled exactly
as the label we want — a substring match credits `app` to `mapping` and `approve`) →
**leak guard** → **dedup** → **coverage report**.

The leak guard asks four questions, because no three of them were enough:

| check | catches |
|---|---|
| substring | verbatim reuse |
| contiguity | an eval sentence wrapped inside a longer one — Jaccard is symmetric and cannot see this; two real leaks got in that way |
| ordered ratio | an eval sentence split up by inserted words — one phrase in the middle slipped 124 of 188 references past contiguity |
| token containment | an eval sentence **reordered** — every order-preserving check is blind to it |

It also strips invisible characters (U+200B injected every third character walked 263 of
264 references through an earlier version, while rendering identically), and it **fails
closed** on a missing *or empty* manifest — several are gitignored, so a fresh checkout has
none of them, and a guard armed against nothing reports success.

### 3. Record

```sh
benchmark/.venv/bin/python benchmark/finetune/record.py --verify
```

Hold `Space`, speak, release. The clip uploads and the next sentence is up before you
let go. No listen-back step — QC is automatic:

* rejects silent, clipped, too-short and noise-swamped takes on the spot, and never
  writes a rejected take into `clips/`
* `E` edits the sentence. **Use it.** If you naturally say it differently, fix the text
  to match what you actually said — a label that disagrees with its audio is the most
  damaging thing in the set
* `E` on an **already recorded** item forces a choice: *the audio already says this*
  (relabel, and it goes back through verification) or *re-record*. Silently keeping the
  old audio under a new label is the one thing this app exists to prevent
* `--verify` transcribes each take with typhoon in the background and flags takes where
  the audio doesn't contain the sentence at all. This is not measuring the model — the
  model is *expected* to fail on the terms. It catches **you**: a line misread, a word
  skipped, the wrong row read twice. **`export.py` refuses any take without a clean
  verdict for that exact recording**, so recording without `--verify` produces nothing
  shippable

**Record across days, rooms and microphones** (MacBook mic, AirPods). The app tags the
device automatically. Variety is what makes the finetune survive contact with real use;
a corpus recorded in one sitting in one voice teaches the model that sitting. Note that
System Settings ▸ Sound holds the mic open and pins AirPods into HFP — quit it first.

### 4. Export

```sh
python3 benchmark/finetune/export.py
```

`train.jsonl` / `val.jsonl` as `{"audio": path, "text": label}`. Val is held out **by
sentence**, so a re-recorded line cannot straddle the split and turn the val score into a
memorisation score.

Export **fails closed**. A take ships only when a verifier verdict exists *for that exact
take hash* and says the audio matches. Missing, pending, unjudged, stale and flagged all
mean "not shipped" — the earlier version treated missing verdicts as clean, which waved
through precisely the takes with no evidence behind them.

## Before you record 1,700 clips

Record **~500**, then run the pilot — the full recipe, with its evidence, is in
`docs/superpowers/plans/2026-07-15-finetune-run.md`. Train and score:

```sh
# TRAIN — from benchmark/.venv. batch 2 is a MEASURED ceiling (4 peaks at 49.6GB on a 48GB
# box and swaps); raise --accum, never --batch. ~35 min for 500 clips, 3 epochs.
BASE=$(ls -d ~/.cache/huggingface/hub/models--chayapats--typhoon-whisper-turbo-mlx/snapshots/*/ | head -1)
benchmark/.venv/bin/python benchmark/finetune/train.py --base "$BASE" --epochs 3 --batch 2 --accum 4

# SCORE — from sidecar/.venv. NOT benchmark/.venv: the Gemma cleanup imports mlx_lm, which is
# broken there (mlx_lm 0.31.3 vs transformers 5.13). NOT eval_models.py either — it pins
# temperature to 0.0 with no fallback ladder and force-feeds initial_prompt, and typhoon
# repetition-loops under exactly that config. eval_cleanup.py calls the real production handler.
export OLIV_TYPHOON_MLX_REPO="$PWD/benchmark/finetune/dataset/model_ft"
sidecar/.venv/bin/python benchmark/eval_cleanup.py --manifest data/manifest_ft_probe.jsonl \
    --engine typhoon-turbo-mlx --no-cleanup --out benchmark/eval_results/ft_tuned_pure_probe.json
```

500 clips will not show you the ceiling. It will show you whether the plumbing works: does loss
fall, does it **not forget**, do the targeted terms improve.

**The forgetting gate is `manifest_ft_probe.jsonl`, not the holdout.** The holdout can no longer
answer that question: 33 of its 40 clips carry terms this corpus trains on (`build_terms.py`
mined the holdout manifest for its keywords, and used its sentences to vouch for repo-mined
words). Term gains and forgetting losses now cancel inside its aggregate. The probe is the 65
eval clips whose spoken text contains **no** trained term (partitioned by reference text, not the
incomplete `keywords` annotation) — regenerate it with `probe.py` after any change to
`script.jsonl`, and re-baseline.

## Files

Local / gitignored (generate or record on your machine):

| | |
|---|---|
| `terms.jsonl` | mined terms, priority, quota, failure evidence |
| `TERMS_REVIEW.md` | human-readable view; the P2 section is the ask |
| `terms_manual.txt` | **you edit this** |
| `script.jsonl` | the sentences to record |
| `_generated.json` | raw Claude sentence dump before `build_script.py` |
| `dataset/takes.jsonl` | one row per accepted take, append-only |
| `dataset/edits.jsonl` | sentence corrections; applied over `script.jsonl` on load |
| `dataset/verify.jsonl` | typhoon's transcript + misread flag, keyed by take hash |
| `dataset/clips/` | 16 kHz mono PCM16 — QC-passed takes only |
| `dataset/raw/` | original browser upload, kept for forensics |

Audio in `dataset/`, plus `terms*`, `script.jsonl`, `TERMS_REVIEW.md`, and
`_generated.json`, are personal corpora and stay local (gitignored). Only the
tooling (`*.py`) and this README belong in git.
