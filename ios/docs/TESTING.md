## Host keyboard crash and Safari completion — 2026-10-30

**Keyboard missing in some apps (fixed).** Two device crash reports from build 14 (`OlivKeyboard`, iOS 27.0.1) share one stack: `viewDidAppear → requestBridgeEvent → refreshFocus → UUID._unconditionallyBridgeFromObjectiveC`, `EXC_BREAKPOINT`/SIGTRAP. Swift imports `UITextDocumentProxy.documentIdentifier` as non-optional, but the remote proxy returns nil whenever no host text session is attached. A probe logged nil in every `viewDidLoad`, before the first document callback, and in every `viewWillDisappear`. `viewDidAppear` arrives through UIKit's queueing proxy and can land after a host has already dropped focus. The trap killed the extension, so the field showed no keyboard until it was refocused (the "tap elsewhere, tap again" report). The crashing path requires Full Access.

Reproduction: a temporary Debug fixture focused and resigned a UITextView 80–220 ms apart while posting focus-refresh requests. On the same simulator with OLIV + Full Access and the same 60 iterations, the original code ended in **3 SIGTRAP terminations** (`termination reported by launchd (2, 5, 5)`, 4 extension processes). The fix ended in **0 terminations** with one process. Every read now goes through `KeyboardHostDocument`, which reads the getter through the Objective-C runtime and treats nil as "no host session" (bridge refresh/delivery, delete-hold context, word completion, vertical cursor). Regression: 202 unit tests (3 new) and 30 real-extension UI cases (Feel, Touch, multi-host Delete and the 7 dictation bridge cases) pass on the iPhone 17 Pro iOS 27 simulator. The fixture was removed after verification.

**Safari inline URL completion (still a platform limit).** Reproduced in Simulator Safari after visiting example.com: typing `exa` shows `exa|mple.com — Example Domain`. OLIV Delete gives `ex` and Safari immediately re-completes. Apple's keyboard first leaves `exa` without completion, then deletes without re-completing. The proxy reports `before="exa"`, `selected=nil`, `after=nil` with the completion visible, so it is invisible to the extension. Twelve public alternatives were tested on the first Delete, and none dismissed the completion: `deleteBackward`, `insertText("")`, `unmarkText`, empty/space marked text with commit or delete, zero/left-right cursor moves, space-then-delete, and rewriting the prefix through marked text. Safari distinguishes its own Delete key from extension edits; similar reports exist for SwiftKey ([Mozilla 1209052](https://bugzilla.mozilla.org/show_bug.cgi?id=1209052)). No workaround is shipped.

### HTTP 400 from iPhone WAV padding

The first physical recordings exposed a compatibility gap after key setup. Apple's recorder wrote valid PCM16 mono 16 kHz WAV with `JUNK`, `fmt `, `FLLR`, and `data` chunks. The deployed backend at `oliv-windows` commit `496ca5e` rejects `FLLR` in `server/oliv-api/src/audio.rs`; `api.rs` maps that validation failure to HTTP 400 before inference. Build 2 canonicalizes WAV at the dictation upload boundary to the same 44-byte `RIFF`/`fmt `/`data` form used by Linux. The earlier tests verified local WAV decoding but did not exercise this public backend's stricter chunk allowlist; regression coverage now includes the actual Apple container structure.
