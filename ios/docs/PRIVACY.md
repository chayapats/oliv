# OLIV data handling

OLIV records only after a user invokes capture. Idle and ordinary keyboard typing have no active OLIV audio session or metering loop. The main app releases the recorder and deactivates its audio session before transcription/network processing begins. Recording stops after two minutes, on stop/cancel, or on an audio interruption/route loss. Toggle’s **Action button auto-finish** is on by default: after speech, 1.5 seconds of classified non-speech finishes capture. No initial speech cancels after eight seconds plus up to 1.5 seconds of detector grace. The separate pause-stop preference for other recordings remains off by default. The keyboard never starts recording or keeps a microphone session alive.

Build 7 replaces native SoundAnalysis with an approximately 1.2 MB bundled Silero voice-activity model, converted from official v6.2.3 weights. Core ML runs it with CPU-only compute during active capture to detect speech; it does not transcribe words or make another cloud request. It stops with capture and has no idle audio feed. The compiled model ships inside the app, requires no runtime download or additional permission, and uses no GPU. The bounded device background-capture probe passed; Action button end-to-end validation remains pending. See [test evidence](TESTING.md#automatic-finish--build-7).

Recording and original cleanup options are saved in private Application Support before upload. Audio and submitted cleanup text go only to the configured OLIV endpoint, which the user sets in Settings (a release build may prefill an operator's server). An HTTPS server needs no private VPN. HTTPS uses normal certificate and hostname validation, and redirects are rejected. Optional custom private HTTP requires explicit opt-in and a local/private address; the old address-specific ATS exception has been removed.

Each iPhone should use a new individual API key. Scope `dictate` covers recording transcription and its cleanup; standalone text cleanup separately requires scope `clean`. The old shared token is retired. The bearer key uses Keychain AfterFirstUnlockThisDeviceOnly protection so user-triggered capture can finish after locking. It is not synchronized, written to preferences/pending recordings, logged, or shared with the widget or keyboard. Configuration, history and audio are excluded from backup and use device file protection.

Editing an endpoint does not forward the old token to it: authenticated processing requires an explicit Save. An unsaved address can receive an unauthenticated health check only. A one-way binding of the saved address and token also prevents a partial settings/Keychain write from pairing a credential with the wrong saved server.

Migration of the legacy default stages the public HTTPS address, disables private HTTP and clears that binding; a new key must be explicitly saved before authenticated requests can resume. It preserves custom endpoints, vocabulary, replacements, history and pending recordings. **Test connection** sends unauthenticated public health only. It does not transmit the saved key, audio or text, does not call cleanup, and does not verify key scope or model availability. Requests identify the client as `oliv-ios/0.1.0`.

Successful audio is deleted after text is stored. When history is disabled, the main app's current result stays in memory and successful audio is deleted; an explicitly requested keyboard delivery can still temporarily store that result in the shared container described below. Failed uploads retain audio for manual retry with the original options. Cancelling processing retains retry audio: cancelling the client cannot retract work accepted by the server.

Rate-limit cooldown storage contains only the next eligible request date, never a key, transcript or audio. It persists across launches and server/key changes. During cooldown, new audio remains pending without an inference request; OLIV does not poll, sleep-loop or retry automatically.

History keeps up to 1,000 entries. Delete entries/all history or individual failed recordings in the app. Invalid interrupted WAVs are preserved in the private Interrupted folder. Force-quit while recording can produce an unrecoverable partial WAV.

Automatic foreground copy can be disabled. Copies are device-local and expire after five minutes. The app never reads the clipboard in the background; text import uses the system PasteButton. A user-created Shortcut controls its own clipboard behavior. Live Activities show time/status, never transcripts or tokens.

The optional OLIV keyboard needs **Allow Full Access** to write focus information to its App Group and receive a requested dictation. It does not make network requests or upload ordinary typing. Shared storage contains only short-lived document/focus identifiers, revision/timestamps, a SHA-256 context digest and the single dictation result awaiting insertion. Surrounding typed text, credentials, audio, history and server settings are not placed there. The digest is used only to detect context changes. Ordinary typing still works with Full Access disabled; automatic delivery does not.

The keyboard answers explicit focus-refresh notifications. There is no idle polling or heartbeat. Delivery checks the original focus again and is consumed at most once. A changed field, canceled/failed capture, no-speech result, retry or standalone cleanup cannot produce a new automatic insertion. Focus eligibility lasts six seconds between verified events; payload eligibility expires after 60 seconds. Consumed text is removed immediately. Expired unconsumed text is pruned on the next bridge operation, not by a background deletion timer. Receipts retain only session identifiers and expiration dates for up to five minutes of validity. Shared files are protected until first unlock and excluded from backup. See [keyboard architecture and acceptance checks](KEYBOARD.md).

No analytics, ads, bundled transcription model, always-on microphone, silent-audio keepalive, or dictation-content logging is included. The configured server's retention and operational policy are separate and are not changed by this app.

To diagnose Action button and keyboard handoff failures, each executable keeps at most 40 local event records in its own private `Application Support/OLIVDiagnostics/events.json`. These contain fixed event names, timestamps, fixed state categories, and optional numeric error codes with an allowlisted error domain. They never include error descriptions, userInfo, audio, transcripts, typed text, context hashes, document identifiers, server URLs or keys. The files are mode 0600, protected until first unlock and excluded from backup. Events are written only during explicit capture or keyboard lifecycle/handoff operations; ordinary typing after focus is invalidated and idle time produce no recurring log work. No events are uploaded automatically.
